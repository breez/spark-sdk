# Migrating to the uniffi-dart Flutter package

The Flutter package's Dart API is now generated by [uniffi-dart](https://github.com/Uniffi-Dart/uniffi-dart) from the same definitions as the Kotlin, Swift and other bindings, instead of by flutter_rust_bridge. The package no longer depends on the `flutter_rust_bridge` runtime, so it can sit next to any other package in your app regardless of the flutter_rust_bridge version those use.

Method names and request types are unchanged. Most of the migration is renaming classes, and the compiler points to every place that needs a change.

## Requirements

- Flutter 3.38 or later. A build hook bundles the native library.
- `BreezSdkSparkLib.init()` is gone. Delete the call: the library loads on first use.

## Renamed classes

| Before | After |
|---|---|
| Enum variants: `SdkEvent_PaymentSucceeded`, `InputType_Bolt11Invoice` | `PaymentSucceededSdkEvent`, `Bolt11InvoiceInputType` |
| Errors: `SdkError`, `SdkError_InsufficientFunds` | `SdkException`, `InsufficientFundsSdkException` |
| Other error enums: `DepositClaimError_MissingUtxo` | `MissingUtxoDepositClaimException` |
| Unnamed variant fields: `inputType.field0` | `inputType.v0` |
| Variant constructors: `Seed.mnemonic(mnemonic: m, passphrase: null)` | `MnemonicSeed(mnemonic: m, passphrase: null)` |
| Single-field variants: `PaymentRequest.input(input: s)` | `InputPaymentRequest(s)` |

The rules: a variant class is the variant name followed by the enum name, and `Error` becomes `Exception` in the names of error types. A variant with one unnamed field takes it as a positional argument.

```dart
// Before
if (event is SdkEvent_PaymentSucceeded) { ... }
try { ... } on SdkError_InsufficientFunds { ... }

// After
if (event is PaymentSucceededSdkEvent) { ... }
try { ... } on InsufficientFundsSdkException { ... }
```

## Other changes

- **Constructors are not `const`.** Remove `const` in front of SDK types, such as `const GetInfoRequest(...)`.
- **Optional arguments.** Fields of request types that can be null stay optional. Function and method arguments that can be null are required: pass `null` explicitly, for example `initLogging(logDir: null, appLogger: logger, logFilter: null)`. Variants with several fields also take their nullable fields as required arguments.
- **`SdkBuilder`.** Its `with...` methods are asynchronous and change the builder in place: `await builder.withDefaultStorage(storageDir: dir)`, then `await builder.build()`.

## Events and logs

`addEventListener` and `initLogging` take listener objects instead of returning streams. `addEventListener` returns an id that `removeEventListener` accepts. To keep using streams, forward the callbacks to a `StreamController`:

```dart
class SdkEventStream implements EventListener {
  final _controller = StreamController<SdkEvent>.broadcast();

  Stream<SdkEvent> get stream => _controller.stream;

  @override
  Future<void> onEvent(SdkEvent event) async => _controller.add(event);
}

class SdkLogStream implements Logger {
  final _controller = StreamController<LogEntry>.broadcast();

  Stream<LogEntry> get stream => _controller.stream;

  @override
  void log(LogEntry l) => _controller.add(l);
}

final events = SdkEventStream();
final listenerId = await sdk.addEventListener(listener: events);
events.stream.listen((event) { ... });

final logs = SdkLogStream();
initLogging(logDir: null, appLogger: logs, logFilter: null);
logs.stream.listen((entry) { ... });
```

Don't let an exception escape `onEvent` or `log`. The SDK calls them from its own threads and has no way to report the error, so it panics, which can stop the app. Forwarding to a `StreamController`, as above, keeps your handlers' errors on the Dart side.

## Passkeys

`PasskeyClient` takes its PRF provider as an argument, as in the Kotlin and Swift packages. Pass the built-in `PasskeyProvider`, which takes the provider options that used to go in the config:

```dart
final passkey = PasskeyClient(
  prfProvider: PasskeyProvider(PasskeyProviderOptions(rpId: '<your-rp-domain>')),
  breezApiKey: '<breez api key>',
  config: null,
);
```

`PasskeyClient.fromCallbacks` and `PasskeyClientBuilder` are gone. For a custom PRF backend, implement `PrfProvider`. Passkey failures are typed: catch `PrfPasskeyException` and check its `v0`, for example `e.v0 is UserCancelledPrfProviderException`.

## Interfaces you can implement

Flutter apps can now implement the SDK's interfaces in Dart, as the other bindings do: `EventListener`, `Logger`, `PrfProvider`, `CpfpSigner`, `BitcoinChainService`, `Storage`, `SessionStore`, `RestClient`, `FiatService`, `PaymentObserver` and the external signer interfaces. This replaces these Flutter-only calls:

| Before | After |
|---|---|
| `recoverFundsWithSigner(signPsbt: ...)` | `recoverFunds(request: ..., signer: MyCpfpSigner())` |
| `recoverFunds(signerSecretKey: key)` | `recoverFunds(request: ..., signer: singleKeyCpfpSigner(secretKeyBytes: key))` |
| `BitcoinChainServiceHandle` from `newRestChainService` | the `BitcoinChainService` that `newRestChainService` returns |
